# Patches

Each numbered patch modifies the vendored Butterscotch source in `upstream/` for MiaUI. They're applied in order by the `Dockerfile`:

| # | File | What it does |
|---|---|---|
| 001 | `001-rg35xx-fallback-mapping.patch` | Adds `createFallbackMappings()` — the shipped `gamecontrollerdb.txt` has no entry for the RG35XX pad, so a fallback mapping is created on boot. Face buttons are identity; the D-pad is remapped to the verified MiaUI indices (sdl 13–16). Button 12 is the system volume key and is never mapped. |
| 002 | `002-chunklog.patch` | Logs each `data.win` chunk as it's parsed (`logInfo`), so hangs in the loader are visible in `debug.log`. |
| 003 | `003-stage-markers.patch` | Prints `[stage]` markers to stderr at each engine init step (parse, VM create, platform init, renderer, audio). |
| 004 | `004-sdl-error.patch` | Includes `SDL_GetError()` in the SDL2 "Failed to initialize SDL" message. |
| 005 | `005-sdl1-error.patch` | Same as 004 but for the SDL1 backend (`sdl1.c`). |
| 006 | `006-fpslog.patch` | Per-frame phase timing — prints an `FPSLOG:` line every 300 frames via unbuffered `logError`, splitting the frame into input, simulation, and sleep phases. |
| 007 | `007-joyname-cache.patch` | **Performance fix.** Caches `SDL_JoystickName()` per slot. SDL 1.2's version opens the device and issues evdev ioctls on every call (~50 ms/frame on this pad), which was the root cause of a previous bug where the game was running at ~15 fps. |
| 008 | `008-exit-cursor.patch` | Select + Start held together quits cleanly; the fbcon stub cursor (which never moves and sits in a corner) is always hidden. |
| 009 | `009-am2r-string-placeholder.patch` | **AM2R text fix.** Backports Butterscotch `c1260061` "support placeholder substitution in string()" (issue #486) into the pinned tree's APIs: `string()` now substitutes `{n}` argument placeholders and `{{`/`}}` escapes. Without it, every AM2R formatted string renders as `[!]`. Adapted to the pinned tree: single-arg `RValue_toString` (malloc'd result, freed by the patch), no `REQUIRE_ARGC_AT_LEAST` macro, old-style argc check. |
| 010 | `010-am2r-overlay-read-guard.patch` | **Crash guard + diagnostics.** On-device, an overlay-FS text read hit `malloc(0x80000000)` (ftell returned `LONG_MAX`) and SIGABRT'd the game ~13 frames in (`overlay_file_system.c:156`). Both `overlayReadFileText` and `overlayReadFileBinary` now refuse sizes < 0 or > 256 MB, printing `AM2R diag: ... size=... path=...` (unbuffered stderr → `debug.log`) so the offending path is identifiable, and fail the read gracefully instead of aborting. **Root cause found via the diag line:** the game opens the path `./` (a *directory*) as a text file — on Linux `fopen` on a directory succeeds and `ftell` gives `LONG_MAX` (Windows refuses, so the original never saw this). The guard correctly fails the read. Separately, the `[!]`-everywhere text bug was **missing `lang/` on device** — AM2R 1.1 keeps dialogue in external `lang/english.ini` (like the music); the folder was never pushed. |
| 011 | `011-am2r-delta-clamp.patch` | **Fall-through-floor fix.** `runner->deltaTime` is handed to the game unclamped; on-device room/texture loads stall single frames up to 408 ms (FPSLOG `max=`), so any `delta_time`-driven movement tunnels through floors ("sometimes I fall into the map"). Clamps the reported delta to 100 ms; fixed-step scheduling is unaffected. |
| 012 | `012-am2r-conv-array-diag.patch` | **Diagnostic (temporary).** Logs `VM: [script] handleConv(convKey=..): converting ARRAY to string!` whenever a to-string conversion receives an array — the source of `<array:XXXXX>` leaking into the on-screen button prompts. `lang/english.ini` (pushed 2026-11-13) fixed the general `[!]` text; this targets the remaining prompt case. |
| 013 | `013-am2r-activate-grid-readd.patch` | **Collision fix.** `instance_activate_all/object/region` only flipped the `active` flag; the spatial collision grid never re-inserted a reactivated instance, so anything removed from the grid while inactive stayed **permanently collision-invisible** (collision queries iterate grid cells and skip `!active` — a grid-less instance is unreachable). Fixes "collision breaks after the pause menu". Also logs `AM2R diag: activate_* re-added grid-less instance ...` to prove the loss path. |
| 014 | `014-am2r-strip-caller-diag.patch` | **Diagnostic (temporary).** Logs whenever `SpatialGrid_markInstanceAsDirty`'s removal branch (strip) actually removes a dirty inactive instance, with the call-site return address (`AM2R diag: grid-strip ... ret=...`). Run #6/#7 showed 0 hits — the strip path is not involved in the floor-loss. |
| 015 | `015-am2r-retaddr-diag.patch` | **Diagnostic infrastructure (temporary).** Makes `RValue_toString` `noinline` and logs its ARRAY-case call-site return address (`AM2R diag: array-to-string from ret=0x...`), so the caller builtin can be decoded offline against `out/syms.txt`. This is how runs #6/#7 identified `builtin_string_width` and `builtin_draw_text` as the array consumers. |
| 016 | `016-am2r-syncdrop-diag.patch` | **Diagnostic (temporary).** Logs instances dropped by `syncGrid` (bbox-invalid), with objectIndex — run #7 shows only 8 sprite-less movers (148xxx, `spr=-1 mask=-1`), which are excluded from the grid by design. |
| 017 | `017-am2r-stale-dirty-flag-fix.patch` | **Grid hygiene fix.** `syncGrid`'s skip branch (inactive/destroyed dirty instance) left `spatialGridDirty` set and cleared the dirty list, so every later `markInstanceAsDirty` early-returned and the instance could never re-enter the grid. The skip branch now clears the flag (and the `markDirty` removal branch clears `collisionCells`). Necessary but not sufficient — run #7 still showed the re-add storm, so the remaining mechanism is elsewhere (see 019's analysis in §17). |
| 018 | `018-am2r-text-array-diag.patch` | **Diagnostic (temporary).** `builtin_draw_text` (args[2]) and `builtin_string_width` (args[0]) dump array-shaped text args: script name + legacy array shape (`rows`, row lengths, first 8 elements). Run #7 decoded: `draw_text_shadow` receives a 1-element legacy array whose sole element is the *correct* string (`"| - Select"`). |
| 019 | `019-am2r-script-shadows-builtin.patch` | **Root-cause fix for the `<array:...>` prompt text.** The VM's `FuncCallCache` resolved `Call.i` names *builtin-first*; AM2R defines its own `string_split(str, num, delim)` script (returns the num-th segment as a STRING), but the runner's array-returning GMS2-style builtin shadowed it, so `draw_txt_1button`'s `p_text1 = string_split(...)` became a 1-element array and string_width/draw_text rendered `<array:...>`. Found by disassembling `gml_Script_draw_txt_1button` on-device (`butterscotch --disassemble '*' data.win`, exits before display init — safe over adb) and grepping the game's 351 script names against the 859 `builtin_*` symbols: `string_split` is the *only* collision. The cache now prefers the game script (native GameMaker semantics). |
| 020 | `020-am2r-sync-insert-diag.patch` | **Diagnostic (temporary).** Logs every `syncGrid` insert of a formerly-grid-less instance (`AM2R diag: sync-entry ...`) with the dirty-source return address, plus a heart-beat proving whether syncGrid still runs after the pause. |
| 021 | `021-am2r-noqueue-drop-diag.patch` | **Diagnostic (temporary).** Logs the two remaining silent grid-loss paths: `spatialGridDirty` set while the instance is NOT in the dirty list (queued-while-active, inactive-at-sync), and the sync-drop of bbox-invalid instances (raises the fixed sync budget of 80 first). |
| 022 | `022-am2r-silent-path-diag.patch` | **Diagnostic (temporary).** Logs queued instance ids that no longer resolve in `instancesById` at sync time (`sync-null`), and the branch that silently skips cells==0 instances. |
| 023 | `023-am2r-grid-swap-queue-flush.patch` | **Fall-through fix, part 1.** When a room swap creates the new spatial grid, the old grid's `dirtyInstances` list (pointing at still-relevant instance ids) was dropped unflushed; room-change restore therefore lost pending grid insertions. Saved instances were also snapshotted with stale `spatialGridDirty` queue state from the dead grid. Flushes the queue into the new grid and requeues dirty saved instances on restore. |
| 024 | `024-am2r-query-probes.patch` | **Diagnostic (temporary).** Probes the object-chain resolution (oSolid parent/child chain dump) and collision-query paths to pinpoint why floor instances were still unreachable. |
| 025 | `025-am2r-stream-probes.patch` | **Diagnostic (temporary).** `initRoom` now logs via unbuffered stderr (`AM2R diag: initRoom ...`, survives SIGTERM — stdout `logInfo` was being lost), and logs the streaming controller's (oTestKeys step) deactivate decisions for oSolid-family instances. |
| 026 | `026-am2r-fall-pinpoint-probes.patch` | **Diagnostic (temporary).** Full floor-family state snapshot every 150 frames (`floorsnap`: id/object/active/cells/pos) plus a place_meeting flip caller log — run #15's evidence that 860 floor instances existed pre-pause and only 125 survived the restore. |
| 027 | `027-am2r-save-inactive-instances-on-persist.patch` | **Fall-through fix, part 2 (the real one).** `persistRoomState` freed every *inactive* instance at pause time instead of saving them. AM2R's streaming controller (oTestKeys step) keeps ~7/8 of the room's oSolid floors deactivated at any instant (active only within view±200), so pausing destroyed them and the restore path ("No Create events") never recreated them — the player walked off the surviving pocket of floors into the void ~5 s after unpausing. Inactive instances are now saved with their `active` flag intact. |
| 028 | `028-am2r-persist-room-tiles-across-restore.patch` | **Blue-grass / vanishing-destructibles fix.** Under `--lazy-rooms` the pause transition frees the room payload (`DataWin_freeRoomPayload` frees `Room.tiles`), and the persistent-room restore path re-parses the raw ROOM chunk without running creation code. AM2R's surface rooms ship all three time-of-day tile variants *stacked* (rm_a0h02: night grass `tlSurface1Night` at depth −120/−121, twilight at −110/−111, day `tlSurface1` at −100/−101 + matching BG layers at 100/110/120); room creation code (`load_timeofday_bgs`) deletes the two wrong variants via `tile_layer_delete`. After a pause-restore the raw tiles come back with the night variant *on top of* day (lower depth = drawn later) — the grass turned blue — and every runtime `tile_add` tile from `link_tile`/`link_surface_tile` (the destructible-rock visuals created in instance creation code) was gone while saved `oSolid` instances kept stale `tileid`s. `persistRoomState` now snapshots `Room.tiles` (count can legitimately be 0, hence a separate `hasTilesSnapshot` flag) and the restore path swaps it back in (id-preserving, so `tile_exists`/`tile_delete` keep working), freeing the freshly re-parsed array. |
| 029 | `029-am2r-file-copy-show-message.patch` | **Save-loading fix.** AM2R's save system (`sv6_load_details`, `sv6_load`, `load_stats`, `copy_save`) copies the save file before decrypting/validating it (`file_copy` → `crypt` → `file_text_open_read`), and the corruption path uses `show_message_async`. `file_copy` and `show_message_async` were missing entirely ("Unknown function"), so the copy never existed, the header check read an empty file, the game's own "Save Data Corrupted" handler ran silently — **deleting the real save** (`file_delete` on the original) and bouncing back to the title. `file_copy` is implemented over the FileSystem `readFileBinary`/`writeFileBinary` pair; `show_message`/`show_message_async` are stubs that log the message (`AM2R diag:` line — no native popup layer on this port). |

Patches 001–008 are identical to the Undertale MiaUI port's set (the pipeline
is proven on-device; keeping them byte-identical keeps the two ports' builds
comparable).

## Upstream pin

Pinned at `92ed6b8c3766361a201a69d202bcde5873cdad7e` (`cobaltgit/Butterscotch`,
2026-08-24) — the same commit as the Undertale MiaUI port. This pin retains
the software renderer (`src/sw/`) and the SDL1 audio backend, which the newer
`ButterscotchRunner/Butterscotch` upstream (the active development repo) has
removed; that repo cannot software-render at all in its current state
(`--renderer software` is a hard error there, and `ENABLE_SW_RENDERER` is
referenced but un-definable). The one AM2R-critical change from newer
upstream — the string() placeholder fix — is backported as 009 instead.

## Applying

The `Dockerfile` resets `upstream/` to the pinned commit and applies `patches/*.patch` in filename order. Any mismatch fails the build hard.

To regenerate a patch against the pinned source: reset `upstream/` to the pin, apply the earlier-numbered patches in order, make the edit, and `git diff` it out (see the Undertale port's `tools/gen_patches.py` for the original generation flow).
